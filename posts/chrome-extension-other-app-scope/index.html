Chrome 代理扩展开着，其他 App 也会走机场吗？按应用核对范围

浏览器里启用了“VPN”或代理扩展，不能凭图标推断桌面聊天软件、下载器也经过同一线路。Chrome 官方的 proxy 扩展 API 管理的是 Chrome 代理设置；Windows 另有系统代理与 VPN 设置。具体产品还可能附带独立客户端，因此应以本机配置和实际连接记录确认范围。

先识别你开启了哪一层

在 Chrome 扩展管理页确认扩展名称与权限，再到 Windows“设置 → 网络和 Internet”查看代理、VPN 是否也有已启用的配置。若使用机场客户端的 TUN 或系统代理模式，记录当前模式和分流规则；不要把浏览器扩展开关当成系统 VPN 开关。

做两个应用的同条件对照

  1. 在 Chrome 打开你信任的公开网络检查页面，记录扩展开、关两种状态下的连接结果；测试时不登录敏感账号。
  2. 在另一个应用里完成它自己的网络任务，并同时查看机场客户端的连接记录。若该应用有独立代理设置，也要单独核对。
  3. 只改一个开关，再重复原任务。若其他应用在扩展开关变化后没有对应连接记录，不宜说它被扩展覆盖；若确有记录，还要确认是系统代理、VPN/TUN 还是应用自身设置造成。

示意图：浏览器、其他应用和系统网络设置是三个需要分别查证的范围。

如何写下验收结果

按“应用、开关状态、实际任务、客户端记录”做表，不只比较两个出口 IP。相同 IP 可能有多种原因，单一网页也看不到所有应用流量。若目的是让整台设备走代理，应使用明确支持系统范围的客户端功能，并按各应用实际任务复查；任何扩展都不应被默认当成全设备隐私保护。
